# 三路原生CAN与H723外部RAM方案

> 历史选型研究，保留推导及来源。2026-10-11 已选定 STM32H735VGH6 + Direct SMPS；当前权威入口为[总结分析报告](../总结分析报告.md)及[引脚规划](../引脚规划.md)。本文旧候选建议不覆盖当前方案。

日期：2026-10-11；初稿Docs v0.7.6，适用范围于v0.7.7补充。用户确认：**三路独立原生CAN是必须具备的能力。**外部SPI CAN控制器、同一路CAN接多个插座、额外MCU代管CAN均不能替代这三路要求。三路分别需要收发器、终端/保护设计，并验证同时工作。

**当前范围：本文说明H723如何扩容，不构成基础版必须扩容的决定。**明确树莓派类上位机分工后，先按通信、采集、安全和可选轻量AHRS做片内预算；G474xE与H723xG都列入比较，详见[docs/14](../共性研究/上下位机职责与IMU处理边界.md)。下述8 MiB和144引脚建议仅适用于确需扩容的H723方案。

## 1. 选型决定与建议

H743只有两路原生FDCAN，退出当前产品的合格主控候选；现有H743VIH6引脚表保留为迁移输入，不能作为满足新需求的投板依据。H723具备三路原生FDCAN，精确封装和外部RAM尚未冻结；它不是唯一满足控制器数量的候选。

**可以通过外部RAM让H723拥有远大于H743的工作数据容量，但不能使它获得同等数量、同等延迟的片内SRAM。**需要扩容时可评估“H723＋8 MiB级Octo-SPI PSRAM/HyperRAM”，采用片内实时工作区与片外大容量工作区分开管理的架构。8 MiB是容量候选，须以实际预算决定是否装配及具体容量，不是已证明必须消耗的内存。

若H723方案需要同时保留多接口与外部RAM，可优先做H723ZG的144引脚资源矩阵，再与H723VG的100引脚方案比较；不扩容的基础版重新按实际接口选择封装。从VG换到ZG并不会增加片内RAM，收益在于更多引脚和外部存储接口选择。

### 1.1 H723板上的W25Q128JVPIQ是什么

2026-10-11补充：用户观察到许多H723板没有外部RAM，而配有W25Q128JVPIQ。核验结果：该器件属于**串行NOR Flash**，容量128 Mbit＝16 MiB，支持SPI/Dual/Quad接口；Winbond 2025选型手册列出2.7～3.6 V、WSON-8 6×5 mm封装。它增加非易失存储空间，不增加H723的运行RAM。来源：[Winbond官方选型手册，W25Q-JV表](https://www.winbond.com/export/sites/winbond/product-selection-guide/file/2025-Product-Selection-Guide-Winbond-Code-Storage-Flash-Memory.pdf)。

| 存储 | H723xG方案容量 | 合理用途 |
| --- | --- | --- |
| 片内Flash | 1 MiB | Boot、主程序、只读常量 |
| 片内RAM | 560 KiB非备份区，另有4 KiB备份区 | RTOS任务栈、控制状态、IMU/AHRS工作区、通信队列；仍需分区和DMA可达性预算 |
| 外部W25Q128JVPIQ | 16 MiB NOR Flash | 升级/回退镜像、标定、配置、只读资源，以及受控写入的故障记录 |
| 外部PSRAM/HyperRAM | 本项目暂不要求标配 | 片内RAM确有缺口时增加工作数据容量 |

这一搭配的工程解释是“片内RAM承接实时工作，外部Flash保存较多持久数据”。尚未逐板审查其固件，不能仅从器件存在推断它已实现OTA、回退或外部执行功能，也不能据此认定任意负载的RAM都够用。

NOR需要擦除和编程，不能当作任意反复修改的普通RAM。W25Q128JV数据手册说明页编程最多256字节、最小扇区擦除4 KiB；即使通过OCTOSPI内存映射读取常量或执行代码，也不会变成可供任务栈、堆或DMA接收环使用的SRAM。擦写应放后台并考虑寿命、掉电一致性及与映射读取的互斥。依据：[Winbond W25Q128JV原厂数据手册，Rev D，2017-05-02，§1/§8.2.13，LCSC托管副本](https://datasheet.lcsc.com/datasheet/pdf/cf3e7cd7501b4484ab05b628ac6261a9.pdf?productCode=C111478)。本次用于核验基本存储语义，不作为最终采购修订依据。

针对A1，若最终选择H723，可先评估“**片内RAM＋一颗串行NOR，无外部RAM**”。W25Q128JVPIQ仅作为16 MiB NOR候选，尚未冻结BOM；Flash容量按升级镜像、配置和记录分区决定。外部存储的回退副本也不会自动将H723单Bank内部Flash变为双Bank，仍需可靠Boot和断电恢复设计。G474候选和三路原生CAN硬要求保持不变。

## 2. 三种扩展方法

| 方案 | 能提供什么 | 主要代价 | 项目判断 |
| --- | --- | --- | --- |
| Octo-SPI接八线PSRAM/HyperRAM | 数MiB级、可内存映射读写的大缓冲；按协议与具体型号选择容量 | 命令/地址/等待周期、刷新、Cache未命中及总线竞争；DQS/RWDS与延迟校准；约11根总线信号，另计复位或差分时钟 | 首选研究路线，先评估8 MiB级、带数据选通信号的器件 |
| FMC接16位SDRAM | 可内存映射的大容量工作区 | 数十根信号、时序与刷新配置、PCB布线和引脚占用；所比较H723的100引脚封装不提供该接口能力 | 144引脚候选方案；有更大连续数据负载时再与串行RAM实测比较 |
| FMC接并行SRAM/PSRAM | 容量扩展，部分器件可减少刷新相关控制工作 | 地址/数据线较多；100引脚缺少完整非复用地址线，可能需地址锁存和额外逻辑 | 本板暂不优先，不能只按“支持FMC”就认定100引脚可直连 |

依据[H723 DS13313 Rev 5，表1、§3.17/3.18](https://www.st.com/resource/en/datasheet/stm32h723vg.pdf)及[ST AN5050 Rev 14，§3.3.3](https://www.st.com/resource/en/application_note/an5050-getting-started-with-octospi-and-hexadecaspi-interface-on-stm32-microcontrollers-stmicroelectronics.pdf)。PSRAM/HyperRAM属于运行内存；原规划QSPI NOR和TF属于非易失存储，不能替代上述RAM。

可参考的容量/电压实例是Infineon S27KL0642系列：64 Mbit＝8 MiB、3.0 V版本覆盖2.7～3.6 V、HyperBus八位DDR接口。具体订货型号的生命周期不同；[S27KL0642GABHV023官方产品页](https://www.infineon.com/part/S27KL0642GABHV023)本次显示active and preferred，而部分同系列后缀显示不建议新设计或停产。该实例仅证明存在相应器件，尚未完成与H723的供电、时序、布线、驱动和采购兼容审查，不构成BOM选择。

## 3. 哪些差距能补，哪些不能

| 资源差异 | 外部RAM能否补足 | 使用方式 |
| --- | --- | --- |
| 日志、大队列、采集历史、批处理暂存容量 | 能 | 适合放入片外独立内存池，设置上限并统计峰值 |
| 可选算法的大工作区 | 有条件 | 先测Cache未命中和最坏周期；热数据/当前计算块优先留片内 |
| DTCM | 不能扩成片内TCM | H723与H743本来都为128 KiB；关键状态、实时栈保留在这里 |
| AXI/D2/D3片内SRAM容量和确定性 | 不能原位扩展 | 通过把非实时数据搬到片外释放片内空间；DMA按实际控制器检查可达性 |
| FDCAN共享10 KiB报文RAM | 不能 | 三路仍共同分配这10 KiB；软件二级队列不能防止硬件FIFO因搬运不及时而溢出 |
| 内部1 MiB Flash及单Bank组织 | 不能 | 外部NOR可暂存升级镜像，不能让片内Flash变成2 MiB双Bank |
| 片内RAM的ECC条件 | 不自动继承 | 外部器件的完整性能力独立核对；H723超过520 MHz的TCM ECC取舍仍存在 |

例如H723片内非备份RAM为560 KiB，再接8 MiB外部RAM，物理数据容量可超过8 MiB；这不是“8 MiB片内RAM”，也不是一块无需管理的统一堆。初始化前外部RAM不可用，启动栈、异常处理和基础故障路径不能依赖它。

## 4. 建议的内存分工

```text
H723片内
  ITCM        关键代码
  DTCM        控制状态、实时任务栈、当前算法热数据
  AXI/D2/D3   按DMA可达性安排接收环、描述符、短队列与搬运缓冲
  CAN专用RAM  三路FDCAN的过滤器、Rx/Tx FIFO与事件区
       ↓ 有界搬运，按块交接
外部PSRAM/HyperRAM
  日志积压、历史数据、大队列、后台协议数据、算法暂存
独立NOR / TF
  参数、升级暂存、持久日志；不算运行RAM
```

优先保持完整控制与故障处理路径在片内。外部RAM出错时，停止依赖它的扩展功能，并通过片内路径进入定义好的故障状态。对Cacheable区域明确CPU/DMA所有权和缓存维护；初期使用独立外部内存池，不把所有malloc、任务栈和DMA缓冲直接迁入片外。

AN5050提供内存映射机制与跨系列示例，但示例板、DMA拓扑和引脚不能原样套给H723。片外存储一般有更高、受访问模式影响更大的延迟；顺序大块访问与随机小访问必须分别测量。内存颗粒标称带宽、CPU主频和有效读写带宽是不同指标。

## 5. 为什么建议先评估144引脚

2026-10-11补充：**仅三路CAN＋USB FS＋SPI IMU＋四UART＋Quad W25Q128、不加外部RAM时，100引脚VGT6已有无占脚冲突候选**，见[docs/17](H723VGT6接口并发与H743替换评估.md)。其NOR使用PB0/AF4作为IO1、PA1/AF9作为IO3，避开PD12/PD13；当前仅完成静态核对。以下144引脚建议主要针对更复杂的外部存储及新增接口，不是该基础组合的必要条件。

DS13313表1给H723VG的100引脚型号列出1路Octo-SPI接口，H723ZG的144引脚型号列出2路，并提供SDRAM接口能力。144引脚可以研究将RAM与NOR放在独立外部存储接口上，减少共享外部总线带来的仲裁和配置切换；仍需验证全部信号与以太网、SDMMC、串口等能否同时分配。

100引脚并非不能接外部RAM，但现有分配要重做：

- PD12/PD13必须让给第三路FDCAN，原QSPI IO1/IO3不能继续占用。
- 数据手册表7列有其他Octo-SPI管脚，例如PB0可承载P1_IO1，PA1或PA6可承载P1_IO3；这些又分别涉及当前RGB、TIM2、IMU SPI1等功能。这里只列出冲突实例，没有确认整组存储信号可用。
- 若RAM占用可引出的Octo-SPI端口，可评估将后台NOR移到普通SPI。若NOR必须承担高速映射读/XIP，则需重新比较144引脚方案。不能假定加一个片选就能把RAM和NOR当作两个独立、随时可访问的内存窗口。
- 八线存储所需IO4～IO7、DQS/RWDS及复位也要一起核对，不能只解决IO1/IO3。

精确料号、封装和针序暂不更换。两个50Pin板间连接器也要重新分配第三组CAN及收发器控制信号，不能只在固件增加FDCAN3。

## 6. 选择外部RAM时必须核对的H723限制

依据[ES0491 Rev 9，§2.8](https://www.st.com/resource/en/errata_sheet/es0491-stm32h72xx73xx-device-errata-stmicroelectronics.pdf)，重点验证：

- §2.8.6：内存映射写时，写配置关闭DQS会产生错误；对没有DQS管脚的存储器也有相应配置要求。
- §2.8.8：启用DQS输入的单/双/四线SPI读存在限制；不能把八线器件的配置直接用于四线RAM。
- §2.8.13：HyperBus使用DQS时，控制器和存储器需匹配至少六个时钟的延迟设置。
- §2.8.16：Macronix OctaRAM模式MTYP＝011存在8 MiB寻址限制；不是所有PSRAM/HyperRAM统一只有8 MiB上限。
- 还需按所选协议检查对齐、wrap/linear切换、共享总线及误配置条件；不能仅凭“能读写一次”判定可用于普通堆。

这支持先研究带DQS/RWDS的八线方案，不代表所有八线RAM天然兼容。具体型号还要匹配电压、命令、最大片选有效时间/刷新要求、读写掩码、访问宽度和启动复位条件。

## 7. 下一步关闭证据

1. 生成三路FDCAN＋原串口/USB/IMU/SDMMC＋外部RAM/NOR的完整100/144引脚资源矩阵，明确机械尺寸代价。
2. 先列实际片内RAM预算；决定8 MiB外部RAM是标配、可选装配还是后续扩展，并选定满足生命周期/供货的精确器件。
3. 对候选板验证随机/连续、8/16/32位读写、边界、Cache、DMA、冷启动、长时间刷新与温度/电压变化，检查数据完整性。
4. 同时运行三路CAN、串口、IMU、上位通信和日志，测最大周期、FIFO溢出、队列峰值及错误恢复；验证外部RAM初始化失败/不可用时的片内故障路径。
5. 固定内存布局、升级布局与勘误规避配置后，才更新精确MCU、Pin Plan、Stack Interface及BOM。
