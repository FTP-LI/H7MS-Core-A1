# H7MS-Core-A1通用控制平台需求基线

更新：2026-09-15，Docs v0.7.3。**用户已确定的方向：研发通用控制板，脱离特定整机。**本文的分层、验证配置和优先级是据此形成的工程草案；数值性能、器件与接口资源仍待H0复核，并非已完成的产品规格。

## 1. 产品定义

H7MS-Core-A1提供可复用的实时控制核心。相同核心硬件与基础固件可以通过设备配置、协议适配器和不同物理接口底板，用于移动机器人、机械臂、传感采集及自动化台架。应用负责运动学、关节布局、业务逻辑与控制目标；平台负责可靠执行、状态回传和故障处理。

每个版本公布支持的电气接口、协议适配器、控制模式和负载范围。增加同一协议的设备应以配置完成；增加新协议可以新增适配器并重新构建固件，但不应把设备专属逻辑写入BSP、调度器或安全状态机。

## 2. 复用边界

| 层 | 共用内容 | 随应用变化的内容 |
| --- | --- | --- |
| 核心硬件/BSP | MCU、启动、电源、时钟、存储、时间基准、外设驱动 | 通过配置选择已验证资源，禁止动态猜测引脚功能 |
| 接口底板 | 板间电气契约、身份、故障/使能语义 | 电压、电流、收发器、隔离、接插件、线束与供电方案 |
| 平台服务 | 配置校验、通信调度、状态、日志、升级、故障管理 | 启用的设备、周期、限值和故障分组 |
| 设备适配器 | 能力声明、命令/状态接口、错误与超时接口 | 厂商协议、节点寻址、量纲换算和驱动器特性 |
| 应用 | 通过统一接口提交有期限的目标 | 轮/腿/轴数量、运动学、控制算法、上位软件及模型 |

现有`SERVOx`网络名仅表示v0.7引脚标识；软件宜使用`serial_bus_id`与`device_id`等通用概念。UART不是设备协议，CAN-FD也不自带通用电机指令集。

## 3. A1基础要求

编号用于设计和验收追踪；均未完成验证。

| 编号 | 需求 | 关闭证据 |
| --- | --- | --- |
| G01 | 稳定启动、复位默认禁止输出、SWD与恢复路径可用 | 电源/复位波形、损坏固件恢复报告 |
| G02 | 至少一条可靠上位链路；USB/UART使用统一应用语义 | 协议规范、参考客户端、重连/旧命令拒绝记录 |
| G03 | 支持串口和CAN两类设备接入，物理层、协议、模式分别声明 | 两类实际设备台架报告；模拟器结果单独标注 |
| G04 | 设备ID、能力、单位、时间戳、数据有效性与错误语义统一 | 两种配置共用平台服务的演示、适配器接口与测试 |
| G05 | 配置检查引脚/定时器/DMA/总线所有权、节点地址和队列上限 | 冲突配置被拒绝，错误配置不能使能输出 |
| G06 | 周期任务有明确截止时间，通信和日志队列有上限 | 指定组合负载下时序、队列峰值、RAM分区和超时报告 |
| G07 | 命令有序号、有效期和控制权；断联/卡死/节点失联可检测 | 故障注入、停止反应时间与重新使能记录 |
| G08 | 硬件急停/禁止路径及默认状态独立于普通任务执行 | MCU卡死、掉电、复位及断线时的物理输出波形 |
| G09 | 参数/升级有版本、校验和恢复机制，日志不阻塞控制 | 更新中断、损坏配置、存储故障与恢复报告 |
| G10 | 发布包含硬件、固件、协议/SDK、接线、配置与能力矩阵 | 另一工作环境按说明完成构建、接线和测试 |

G03是首轮覆盖方向建议，尚未选定设备品牌或协议。外设标称支持、实际连接、实现驱动和达到组合性能属于不同状态，发布时分别记录。

## 4. 资源规划与裁剪原则

沿用现有v0.7资源作为候选，不增加未经核查的引脚。引脚权威来源为[Pin Plan](H7MS-Core-A1_引脚配置.md)，电气权威来源为[板间接口](06_上下板接口规范.md)。

| 类别 | A1候选 | 通用化要求 |
| --- | --- | --- |
| MCU | H743VIH6，480 MHz，2 MB Flash，约1 MB RAM | 分区预算和并发实测决定适用范围，封装按工艺评估 |
| 上位链路 | USB Device、UART8 | 不绑定具体上位硬件，同一时刻明确控制权拥有者 |
| 设备串口 | 4组TX/RX/DIR，另有UART7 | 声明全/半双工、电气方式和可并发数量；复用资源不重复承诺 |
| CAN | 2组FDCAN逻辑 | 验证底板提供物理层，分别记录经典CAN/FD帧与速率支持 |
| 感知/I/O | 板载IMU、SPI/I²C、ADC、TIM1/TIM2 | 无需IMU的配置可关闭相关应用；PWM/编码器按复用表验证 |
| 存储 | 内部Flash、候选32 MB QSPI、TF | 基础控制与恢复不依赖TF；容量由参数、升级与记录需求推导 |
| 增强 | IMU恒温、RL推理、额外诊断显示 | 按配置独立验收，不阻塞基础平台发布 |

主频/内存取舍见[选型记录](07_主控选型与资源预算.md)。12输出MLP只是容量与推理算例；设备数由静态容量、协议寻址、总线带宽和测试结果共同限制。

2026-09-15参考板复核：结合[DJI A/C、达妙H723和D_MAIN共性分析](11_参考控制板共性需求与选型结论.md)，在H0冻结前明确独立CAN数量与首版网络需求。当前2路FDCAN、4组串口及既有双50Pin仍为待审基线；第三路CAN、PHY、HUB和SPI扩展CAN不自动成为首版必选。电源保护、终端配置、共享SPI时序和硬件禁止路径需要明确的采纳/舍弃理由及验收方式。

## 5. 配置与设备接口草案

配置至少包含：`config_version`、兼容硬件/底板版本、总线实例及物理层、协议适配器、设备ID、支持模式、采样/命令周期、单位与标定、数据过期阈值、限制值、故障分组和控制权策略。

启动时先校验配置，再实例化设备。能力表只公布实际启用并通过初始化的资源；缺失可选设备应禁用相关能力，缺失必需设备则禁止相关控制模式。基础串口/CAN模式不应因为未加载RL模型或未开启IMU而无法启动。

执行器接口候选为位置、速度、力矩/电流目标与状态读取；传感器接口为带时间戳及有效性的测量；I/O接口为有权限和默认状态的读写。每个设备声明支持的子集。**不支持的模式必须拒绝，电流与力矩不能未经标定混用。**设备专属参数通过受控扩展接口暴露，保留配置范围和使能状态检查。

统一命令入口供上位机、传统控制器和可选策略使用。原始总线调试仅限维护状态，不能绕过ACTIVE模式的限制、控制权与安全检查。实时阶段使用有界队列和预分配资源，不能因任意配置产生无限内存或等待。

## 6. 用验证配置证明通用性

以下是建议组合，设备与数值尚未冻结。它们可在台架完成，无需任何特定整机。

| 配置 | 目的 | 测试组合与结果要求 |
| --- | --- | --- |
| P0 基础与故障 | 验证平台服务 | PC客户端＋模拟底板/节点；启动、身份、配置、命令过期、故障状态与恢复 |
| P1 串口设备 | 第一类真实物理链路 | 一条总线先接单设备，再增节点；记录电压、协议版本、报文、反馈与超时 |
| P2 CAN设备 | 第二类协议适配及控制模式 | 另一设备/协议与适配器；记录CAN/FD实际支持、终端、仲裁与错误恢复 |
| P3 传感与I/O | 非关节应用 | 模拟量/数字量或外接传感器；单位、校准、采样时刻、断线与资源冲突 |
| P4 混合并发 | 建立性能范围 | 上位链路＋串口＋CAN＋采集＋后台日志，逐步加载并记录可承诺组合 |
| P5 可选推理 | 验证算法扩展 | 固定模型回放、数值/时序对齐、过期与越界动作拒绝；单独发布结果 |

基础发布覆盖P0～P4及G01～G10。P1/P2必须含真实物理链路和设备，纯模拟通过只能证明软件对应范围。P4覆盖多少端口，产品就声明多少端口的组合性能；未覆盖全部4路串口/2路CAN时，不把全端口并发写成已支持。P5独立，不阻塞基础发布。

每份配置在测试前填写以下字段：

| 字段 | 应填写内容 |
| --- | --- |
| 设备与负载 | 设备/固件版本、节点数、每方向报文字节数、命令/反馈频率、突发与重试上限 |
| 总线与线路 | 串口波特率/CAN各阶段位率、终端、线长、拓扑、转换器、同步机制 |
| 时序 | 采样到状态可用、接令到发出/应用的期限，最大数据年龄和抖动阈值 |
| 故障 | 通信超时、检测到禁止输出的时限、停止方式、分组传播与重新使能条件 |
| 资源 | 固件/各RAM区域预算、栈/队列上限、预留量、日志策略 |
| 环境与证据 | 电压/负载/温度范围、测试时长、重复次数、原始数据与软硬件版本 |

H0必须将拟发布配置的这些字段数值化后再冻结；未知项明确记为TBD，不用统一“200 Hz”替代。性能测试记录观测最大值及条件，不把有限台架测试称为无限条件的保证。

## 7. 首块底板与开发顺序

首块配套板以通用验证为目标，名称待定：提供明确输入范围的电源/保护、身份EEPROM、硬件禁止路径、串口物理层选件、CAN收发器/终端、采样与测试接口。先通过一种串口物理层与一种CAN配置，再按资源矩阵扩展；不同电压/收发器选件须标识并避免误接。

任务顺序为需求与资源矩阵 → 精确MCU/封装复核 → 核心板及验证底板设计 → BSP/协议/安全 → P0～P4 → 基础发布。可选算法沿独立支线开展。当前没有因方向调整而新增PCB、固件或实测结果。

详细步骤见[阶段计划](00_阶段计划.md)，待办与状态见[项目状态](08_项目状态与待办.md)，证据要求见[验收方案](04_总结演示与验收.md)。既有专用应用文档与归档仅用于追溯，不能作为当前平台的前置条件。
