# 固件架构规划

> 版本说明：本文保留 v0.8 输入。当前 v0.9 核心/扩展分工、引脚、连接器和加热要求以[工程规划](工程规划/README.md)为准；电源与通用方法仅在不冲突时沿用。

2026-10-12。当前没有固件工程或已运行版本。

启动层先按锁定版本的 CMSIS/HAL 配置 Direct SMPS，再进入时钟、Flash wait-state、MPU/cache和外设初始化。保留HSI低速调试入口，确认供电/VOS就绪后提高主频。不得用H743/H723的供电模板直接替换。

平台分为 BSP、设备适配器、带期限的目标调度、采样/时间服务、通信协议、故障管理、日志/更新。上位机做整机融合与规划；MCU对每条命令检查序号、有效期和使能状态，并执行本地超时策略。IMU原始测量和可选AHRS结果分开发布。

DMA缓冲放在相应总线可访问的RAM区；CPU关键代码/数据可放TCM，但不能假设全部DMA能访问TCM。缓存维护或不可缓存区必须与缓冲所有权协议一致。任务栈、CAN消息RAM、USB/串口环形缓冲、IMU采样、TF/NOR写队列分别预算，不用“总RAM还有空”代替内存域核查。

三CAN分别配置过滤器与有限队列；四UART各有DMA/空闲帧/超时处理，软件DIR必须等到UART传输完成而非仅DMA完成才释放。TF和NOR写入为低优先级可暂停事务，不阻塞控制或ISR。看门狗只在关键任务均健康时喂狗。

更新层采用[OTA 专题中的网关式方案建议](../OTA/H7MS_OTA可行性与推荐架构.md)：上位机负责联网，应用分块接收到 NOR，独立 Bootloader 验签和安装，试启动后确认或回退。内部 Flash 安装进入停机维护；Boot 与应用必须共享 Direct SMPS 启动约定，Boot 独立提供至少一种维护通道。首版只更新应用，框架、分区及体积尚待构建验证。

后续锁定工具链、CubeH7/CMSIS/HAL版本，提交.ioc、链接脚本和启动代码后，才把此架构转为可构建实现。验收见[验收计划](验收计划.md)及[OTA 实施验证计划](../OTA/分区与实施验证计划.md)。
