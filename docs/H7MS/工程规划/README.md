# H735 核心板与扩展板工程规划

2026-10-17 R4B更新：[当前原生工程核验与针序/BOM](../../../hardware/easyeda-pro/review-native/H735-review.html)覆盖本目录旧版引脚和物料分配。核心改为4组UART＋4路GPIO排针、SPI1 IMU、直立USB/GH、XT30 12–48V供电、两组30触点，上层扩展板须避让核心插拔和热岛。本目录的100触点、SPI4/DMA和布局坐标保留追溯，不能作为当前制造输入。

2026-10-16，Docs v0.9.3-design。当前主控为 STM32H735VGH6，TFBGA100、0.8 mm 球距、Direct SMPS。用户已确认核心板优先保证 CAN、IMU、IMU 加热和一路 USB，三路 CAN 收发器安装在核心板；同时支持同底板和跨部位多 MCU 协作。

**本目录是新一轮工程规划入口。**v0.8 的电源参考和原始来源继续保留，但旧引脚、连接器编号、核心/扩展归属不能直接用于 v0.9。此处已经给出逐球规划和七套无静态引脚/EXTI 冲突的配置；它们尚未通过 CubeMX、EDA/ERC、PCB、时序及实物验收。

生成与检查：`python -X utf8 docs/H7MS/工程规划/validate_resources.py`。脚本只更新本目录生成表与结果，不修改历史 v0.8 表格。对外发布前还需逐球人工审图与独立原理图/网表复核。

电气连接生成：`python -X utf8 docs/H7MS/工程规划/generate_connections.py`；电气规划检查：`python -X utf8 docs/H7MS/工程规划/validate_electrical_plan.py`。先执行引脚表生成，再执行连接生成与检查。静态检查没有替代真实固件编译、EDA/ERC或样机验证。v0.9.1详细电气文件优先于v0.9中同主题的待定描述。

当前先做一款CORE和四款可替换验证板：BASE_CAN、BASE_485、BASE_LINK、BASE_IO；每块均39.8×39.8 mm。实际RM应用扩展另按功能组合设计。系统能力按所选配置声明，不能将各配置的资源上限相加。

本轮生成顺序：`validate_resources.py` → `generate_connections.py` → `generate_connector_pads.py` → `validate_electrical_plan.py`。v0.9.2优先于旧文档的连接器/485待定描述；原始时钟参数仍为v0.9.1。

本版在原生成链之后执行 `generate_compact_plan.py` → `validate_compact_plan.py`。v0.9.3电源/机械/物料输入覆盖旧文档同主题内容；v0.9.2的USB和主板间针序继续有效。
