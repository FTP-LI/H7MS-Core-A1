# H7MS-Core-A1固件架构

更新：2026-09-15。以下为通用平台固件设计草案，尚无实现；需求见[通用平台基线](10_通用控制平台需求基线.md)。

## 1. 分层

```text
Application / Optional Policy
  业务控制、运动学、可选状态估计与RL，只提交统一设备目标
Control / Safety
  控制权、命令有效期、限值、调度、状态机与故障管理
Device Adapters
  统一能力/状态/命令；串口、CAN等设备协议与单位转换
Services
  时间、设备注册、配置校验、日志、参数、升级、底板识别
Drivers
  IMU、加热、QSPI、SDMMC、USB、UART、CAN、ADC
HAL/LL
  STM32H7外设、DMA、Cache和中断
```

设备协议、应用布局和算法必须解耦。同一BSP与服务支持上位命令、传统控制、可选本地算法及安全停止。新增同协议节点使用配置；新增协议添加适配器，允许重新构建固件，但不将设备专属逻辑写入BSP或安全状态机。

设备注册表声明ID、类型、支持模式、单位、时间戳/有效性及故障组；配置检查引脚、定时器、DMA、总线和内存上限。不支持的模式必须拒绝。传感器与I/O也使用设备接口，不强制映射成关节。

## 2. 实时任务候选

下表是调度预算起点，各应用按能力与依赖启用，频率不是平台统一规格。基础串口/CAN配置无需加载IMU控制或RL模型；最终数值按docs/10的负载配置冻结。

| 任务 | 初始频率 | 说明 |
| --- | ---: | --- |
| 软件安全检查 | 1 kHz | 急停、故障、电源和看门狗最高优先级 |
| IMU采样 | 1 kHz | SPI DMA + 数据就绪中断 |
| IMU恒温 | 100 Hz | PID/PI、输出限幅和传感器故障检测 |
| 状态估计 | 500 Hz | 姿态、偏置和有效性 |
| 本地RL策略 | 100～500 Hz | 根据模型耗时和执行器带宽确定 |
| 设备通信 | 100～250 Hz算例 | 实际频率按节点协议、反馈和总线带宽确定 |
| 上位机命令 | 50～100 Hz | 命令带序号和有效期 |
| 状态上报 | 100 Hz起 | 不阻塞控制周期 |
| TF日志写入 | 后台批量 | 双缓冲，不在实时线程等待文件系统 |
| 慢速诊断 | 1～10 Hz | 电池、温度、统计和版本 |

所有启用任务报告平均周期、最大/P99抖动、超时、栈水位、CPU占用和DMA错误。队列有界，进入实时模式前完成分配；设备等待与重试有上限。软件检查周期不代表硬件急停总响应时间。

## 3. 安全状态机

```text
SAFE_OFF
  │ 底板识别、急停释放、无故障
  ▼
INIT
  │ 当前模式必需设备、总线、参数及可选算法校验通过
  ▼
READY
  │ 收到带有效期的使能命令
  ▼
ACTIVE
  │ 超时/急停/过温/欠压/总线或策略故障
  ▼
FAULT
  │ 故障消失且收到明确复位
  └────────────→ SAFE_OFF
```

应用/策略不能直接操作GPIO、电源使能或总线DMA，只能提交带设备ID、模式、单位与有效期的目标。统一安全层检查能力、控制权、NaN/Inf、限值、变化率及所依赖观测的新鲜度；姿态检查只用于依赖姿态的模式。缺失可选设备禁用相关能力，缺失必需设备禁止对应模式。故障恢复需明确复位与重新使能。

## 4. 内存与DMA约束

- ITCM：高频中断和关键控制代码。
- DTCM：控制状态、策略输入输出等热数据；H743的DMA1/DMA2不能直接访问TCM，MDMA可以，须按实际控制器核对可达性。
- AXI SRAM：DMA缓冲、神经网络激活区和大块工作区。
- D2/D3 SRAM：可用作相应外设DMA缓冲与跨任务邮箱，分配前逐DMA控制器核对可达性。
- QSPI：只读模型权重、参数与回退镜像；进入实时模式前完成校验。
- TF：日志与采集数据，使用预分配文件和双缓冲。

对Cacheable的DMA共享缓冲，地址与覆盖范围应按Cache line对齐，并按传输方向及所有权切换执行正确的Clean/Invalidate；也可以为指定缓冲配置合适的非缓存区域。不能依赖偶然一致，也不能把所有DMA和内存区域当成同一种行为。依据：[ST H743 ADC/DMA示例说明](https://github.com/STMicroelectronics/STM32CubeH7/blob/master/Projects/NUCLEO-H743ZI/Examples/ADC/ADC_DMA_Transfer/readme.txt)。

## 5. 存储内容

| 存储 | 内容 |
| --- | --- |
| 内部Flash | Boot、主固件、基础配置与恢复代码 |
| QSPI | 版本化配置、升级/回退数据、标定和故障快照；可选模型包 |
| TF卡 | 长日志、轨迹数据、更新包和测试报告 |
| 底板EEPROM | 板型、硬件版本、能力位和底板校准 |

配置包需包含兼容硬件/底板、资源与设备映射、单位/标定、周期、超时、限值及故障策略。可选策略包至少包含：魔数、格式版本、模型版本、硬件兼容版本、输入/输出维数、控制频率、关节顺序、归一化参数、权重长度和CRC/哈希。

## 6. 上位机协议

帧草案包含魔数、协议版本、消息类型、长度、序号、时间戳、负载和CRC；命令负载含控制权、设备ID、模式与有效期。USB/UART复用应用语义，传输层处理各自帧边界。下列消息名为未实现草案，替代旧关节专用命名，编码与版本待协议设计冻结：

- `HELLO/CAPABILITIES`
- `ENABLE/DISABLE/ESTOP`
- `DEVICE_COMMAND`
- `DEVICE_STATE/SENSOR_SAMPLE/IO_STATE`
- `POLICY_SELECT/POLICY_STATUS`（可选能力）
- `DIAGNOSTICS`
- `PARAM_READ/PARAM_WRITE`
- `LOG_CONTROL`
- `BOOTLOADER_REQUEST`

未知消息、版本不匹配、CRC失败、重复/过期命令及未取得控制权的写操作不能改变输出。CAPABILITIES包含硬件、资源组合、设备协议与模式，不把引脚存在直接当成设备功能。原始总线调试仅在维护状态开放。

## 7. 开发顺序

1. 时钟、MPU/Cache、GPIO、SWD和Fault Handler。
2. USB/UART基本通信、时间戳、内部Flash恢复路径。
3. 资源配置、设备注册、安全状态机和底板模拟器。
4. 版本化协议、PC参考客户端、诊断和控制权管理。
5. 串口/CAN适配器及传感/I/O驱动，单设备台架。
6. 参数/日志服务、多总线调度与混合负载，发布SDK和能力矩阵。

IMU相关算法、恒温、TF扩展日志和本地推理按能力独立推进；对应硬件和错误处理必须在声明支持之前验证。可选推理先完成PC回放与H7数值对齐，再测并发时序，不阻塞基础链路与安全框架。

## 8. 最低测试集

- 配置/资源冲突、设备能力与单位映射、协议/有效期、控制权和状态机测试。
- 两类设备配置共用平台服务、模拟节点与真实物理链路验证；启用推理时再逐样本比较ONNX/H7输出。
- DMA/Cache、TF拔出、QSPI校验失败和日志满故障注入。
- 启用相关能力时验证IMU中断丢失、NTC开短路和加热MOSFET失控检测。
- 急停、欠压、上位机断联、设备离线；启用推理时验证策略超时。
- 每次发布保存源码提交、`.ioc`、配置/SDK版本、固件二进制和报告；启用模型时附模型哈希。
