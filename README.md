# H7MS-Core-A1

**H7MS-Core-A1的目标是通用机器人实时控制核心板。**平台提供设备通信、传感采集、周期调度、目标检查、故障处理和调试升级能力，通过配置、接口底板和协议适配器服务轮式、足式、机械臂及自动化台架等应用。

产品方向已确定为通用平台；接口数量、性能上限与具体器件仍在需求复核阶段。平台不固定机器人品牌、关节数量、上位机型号或策略模型。产品定义见[通用控制平台需求基线](docs/10_通用控制平台需求基线.md)，研究依据见[架构与资源调研](docs/09_机器人上下位机主控架构与资源调研.md)与[四款参考控制板比较](docs/11_参考控制板共性需求与选型结论.md)。

## 1. 产品边界与系统分工

“上位机/下位机”描述任务分工，“核心板/底板”描述电路分工。A1当前采用核心板与接口底板的模块化方案，两者共同组成实时下位机系统。

| 部分 | 责任 | 适配方式 |
| --- | --- | --- |
| 外部上位机 | 视觉、规划、ROS 2、界面与任务管理 | PC、ARM或x86计算平台，通过公开协议和SDK接入 |
| H7MS核心板 | 时间基准、实时任务、设备状态、目标调度、安全与诊断 | 共用BSP和服务，按能力表与配置启用功能 |
| 接口底板 | 电源、保护、收发器、接插件和硬件禁止路径 | 通用验证底板先行，应用底板按电压和物理接口扩展 |
| 外部驱动器/设备 | 电机本地控制环、功率级、设备保护或测量 | 协议适配器映射到统一设备接口 |

```text
PC / ARM / x86上位机：任务、规划、可视化
                 ↕ USB / UART：版本化协议与SDK
H7MS-Core-A1：时间、设备接口、周期调度、安全、诊断
                 ↕ J1/J2：逻辑信号与核心板供电
接口底板：电源与保护、TTL/RS-485/CAN物理层、接插件
                 ↕
智能执行器 / 独立电机驱动器 / 传感器 / I/O模块
```

上位机和执行器分别核算供电，执行器大电流不经过核心板或其板对板连接器。A1首版集中完成实时控制平台；视觉计算、MCU端训练、直接电机功率驱动和EtherCAT不列入当前交付承诺。小型RL推理是可选扩展。

## 2. 通用板必须交付的能力

| 能力 | A1要求 |
| --- | --- |
| 硬件可用 | 可靠供电、时钟、启动、复位、SWD、测试点与可恢复下载 |
| 接口可适配 | 区分MCU逻辑、物理层和设备协议，声明电压、引脚复用和并发限制 |
| 软件可复用 | 统一设备ID、能力、单位、时间戳、命令有效期和故障语义，新设备通过适配器接入 |
| 控制可预测 | 在声明的节点数、报文量、频率和并发负载下验证延迟、抖动、内存峰值与错误率 |
| 故障可处理 | 默认禁止输出，断联/复位/总线故障有明确反应，恢复后重新使能 |
| 平台可交付 | EDA、BOM、固件、SDK、接线说明、示例配置和验收数据对应到同一版本 |

通用性通过不同设备配置共用核心硬件和平台服务来证明。首轮建议验证串口设备配置与CAN设备配置，再测试传感/I/O及多总线混合负载。节点数、周期和控制模式按配置声明，没有报告的能力保持“规划/未验证”。

## 3. 当前硬件候选资源

以下沿用v0.7设计，尚无本板实测；通用定位调整不等于资源已全部冻结。

| 模块 | 当前规划 | 需要关闭的问题 |
| --- | --- | --- |
| 主控 | STM32H743VIH6 / TFBGA100；480 MHz、2 MB Flash、约1 MB RAM | 精确AF/DMA/时钟复核、内存分区与并发预算、封装工艺 |
| 最小系统 | 8 MHz有源HSE、3.3V电源、复位/BOOT0、SWD；LSE可选 | 电源时序、USB双供电、防反灌与恢复 |
| 上位通信 | USB-C Device、UART8；另有UART7扩展 | 统一协议、控制权、重连和吞吐验证 |
| 设备通信 | 4组TX/RX/DIR、2组FDCAN逻辑 | 物理层、适配协议、总线并发；复用资源不能重复计数 |
| 感知与I/O | SPI IMU、I²C、SPI、ADC、TIM1/TIM2等 | 按配置使用，共享引脚/定时器/DMA冲突检查 |
| 存储与增强 | 建议32 MB QSPI、四位SDMMC TF、IMU加热、RGB/蜂鸣器 | 容量依据、并发时延和热保护；RGB与加热共用TIM8待解决 |
| 板间连接 | 两只50Pin连接器、安全握手、底板身份 | 连接器配对、针序镜像、机械、供电和默认状态 |

MCU标称能力依据[ST H743VI](https://www.st.com/en/microcontrollers-microprocessors/stm32h743vi.html)。具体引脚见[Pin Plan](docs/H7MS-Core-A1_引脚配置.md)，电气契约见[Stack Interface](docs/06_上下板接口规范.md)。历史网络名`SERVO1…4`保留为引脚标识，产品层对应通用串口设备总线，不固定舵机品牌或协议。

核心板接收底板5V并产生3.3V，TF卡使用3.3V。BASE_5V持续输入≤1.5 A、辅助3.3V总限流200 mA是待验证设计目标；外部上位机、执行器及USB单供电各有独立预算。

## 4. 主控与开发取舍

- **H743继续作为评估基线。**先确定2路CAN是否足够：H743有2路FDCAN，H723有3路，但H723片内Flash/RAM更少；若必须有第三路片内CAN，则在引脚冻结前重新评估H723。封装按尺寸、生产和调试条件评估。
- **先保证内存和可访问性，再比较主频。**Flash、任务栈、队列、DMA缓冲和算法工作区分别预算；高主频不能补救内存容量或外设冲突。
- **先实现平台基础，再启用应用功能。**优先最小系统、通信、安全、设备抽象与SDK；恒温、TF和RL按配置逐项验收。
- **用负载配置定义性能。**“支持4路串口、2路CAN”需要各自及同时工作证据，不能用一个演示频率概括所有设备。

45→128→128→12 MLP与200 Hz仅保留为可选推理基准，不限定设备数、动作维度或基础控制周期。芯片比较和计算过程见[主控选型与资源预算](docs/07_主控选型与资源预算.md)。

下一步按以下顺序推进：

1. 完善[通用需求与验证配置](docs/10_通用控制平台需求基线.md)，确定接口组合、节点/报文负载、故障时限与电源环境。
2. 决定是否需要第三条片内CAN及首版以太网，再复核精确MCU、引脚、DMA/时钟和封装，解决TIM8共用问题。
3. 完成核心板与通用验证底板的BOM、电源、连接器和保护设计。
4. 实现BSP、安全状态机、版本化协议及PC参考客户端，在模拟节点上验证故障处理。
5. 完成串口设备、CAN设备、传感/I/O与混合并发验证，发布可复现的平台资料。
