# H723VGT6接口并发与H743替换评估

> 历史选型研究，保留推导及来源。2026-10-11 已选定 STM32H735VGH6 + Direct SMPS；当前权威入口为[总结分析报告](../总结分析报告.md)及[引脚规划](../引脚规划.md)。本文旧候选建议不覆盖当前方案。

## 1. 结论及适用范围

STM32H723VGT6存在一套无重复占脚的分配，能同时容纳三路原生FDCAN、USB Device、SPI IMU、四路独立硬件串口和四线W25Q128。因此，**仅为这些接口，不必升级STM32H723ZGT6**。此结论针对引脚及外设实例资源；尚未证明任意速率下都能同时满负载运行。

本轮采用以下明确假设：

- USB为内置PHY的Full Speed Device，线速12 Mbit/s；不包含480 Mbit/s外置ULPI PHY或USB Host/OTG角色切换。
- IMU独占SPI1，预留一个片选和两个中断；另有空脚可加第二片选，实际传感器型号未定。
- 四路串口均包含TX/RX，另预留四个软件DIR用于半双工收发器；不承诺每路同时提供RTS/CTS硬件流控或原生自动DE。
- W25Q128采用普通SPI命令集下的Quad数据传输，使用OCTOSPI1经OCTOSPIM Port 1连接；不要求外部RAM，也不占用IMU的SPI1。
- 时钟按现有8 MHz有源HSE方向预留，保留SWD、NRST、BOOT0及必要电源网络。本文CSV不是包含所有电源脚的完整网表。

H743VIH6约¥50按用户提供的价格作为测算输入，未核对其采购数量、税费、渠道、现货及硅版本。它的大RAM和2 MiB Flash值得考虑，但只有两路原生FDCAN：**三路原生CAN不变时，H743不能等价替换；允许两路或第三路外置时，才构成另一种可选架构。**本次没有修改这项硬性需求。

这是一份新候选，不等于原v0.7全部扩展资源已原样迁移。原Pin Plan和J1/J2针序不在本轮自动替换，避免把研究表误当成制造版本。

## 4. USB与W25Q128的配置边界

### USB

PA11/PA12可直接连接内置FS PHY，不需要为本方案增加ULPI芯片。控制器名字中的HS不代表这两根线提供480 Mbit/s；当前方案为12 Mbit/s Full Speed。

核心板可能由底板供电，因此USB拔出时MCU仍会工作。不能仅“关闭VBUS sensing”就忽略USB接入状态。本候选将PA9留作**GPIO分压/检测＋EXTI**，在固件管理USB attach/detach；此路径不同时开启PA9的原生模拟VBUS检测。原生检测是另一种电路选择，需重新按相应电气条件设计，不能把分压后的GPIO信号直接当成其同等输入。

分压/检测网络必须校核VBUS范围、VIH/VIL、MCU断电时输入限制及反向供电。USB-C Device的CC下拉、ESD、差分布线、供电防反灌及48 MHz时钟仍需要原理图和时钟验证。[ST AN4879 VBUS检测指导](https://www.st.com/content/st_com/en/technical-documents/an4879-introduction-to-usb-hardware-and-pcb-guidelines-using-stm32-mcus-stmicroelectronics_asset/chunk-003-topic-an4879-vbus-sensing-detection.html)

### W25Q128

六根信号全部来自OCTOSPIM **同一个Port 1**，其中IO0～IO3构成四线数据组；不是将两个不同端口的数据线拼接。按OCTOSPI1、Port 1 CLK/NCS及低四位数据配置，不启用Octal、HyperBus、DQS或第二颗存储器。引脚支持混合AF编号，不要求同一总线的每根脚AF数字相同。

W25Q128为16 MiB NOR Flash，具体供电/封装/命令需绑定到如W25Q128JVPIQ这样的完整料号。Quad模式下IO2/IO3不能永久绑成WP#/HOLD#；须按手册处理QE、上电状态、片选上拉、读等待周期和写保护。初期可从低频普通SPI指令读取ID，再验证Quad读与擦写；验证前不承诺最高频率或XIP。

实时代码、IMU和CAN服务不能因后台Flash擦写而全局关中断或长时间阻塞。优先片内执行关键代码，Flash擦写异步管理；外部映射读与擦写互斥、Cache维护及OCTOSPI适用勘误仍需处理，见[存储分析](三路原生CAN与H723外部RAM方案.md)。

## 5. 并发资源与速率还要验证什么

这组分配使用FDCAN1/2/3、SPI1、USART1/2/3、UART4、USB_OTG_HS和OCTOSPI1，各自有独立外设实例，不是多个连接器复用同一个CAN或UART。IMU不与Flash共用SPI事务锁。

后续需完成以下验证，不能以引脚检查替代：

- **DMA/内存：**四路UART全双工若全部使用DMA，需要8条传输流；SPI1收发再需要2条。H723 DMA1/2提供合计16条流，数量上有安排空间；实际请求映射、优先级、AXI/各SRAM可达性、Cache维护及可选SD/RGB占用仍未配置。FDCAN通过专用报文RAM工作，不按每路TX/RX占普通DMA流计算；USB和OCTOSPI传输模式单独配置。
- **CAN：**分配三路共享10 KiB报文RAM，禁止偏移重叠；验证各路仲裁/数据速率、过滤器、FIFO峰值、bus-off及错误风暴。调度优先级要防止Flash/日志挤占收包服务。
- **USB汇聚：**12 Mbit/s是总线线速，不是应用有效吞吐。例如四路UART各3 Mbaud、8N1，接收有效数据已经合计1.2 MB/s，尚未计CAN、IMU、USB与自定义协议开销。必须给出持续与突发流量预算；引脚同时可用不等于USB能无损透传所有接口各自最高速率。
- **时钟：**分别核算CPU、USB 48 MHz、FDCAN、SPI、UART与OCTOSPI内核时钟。CPU主频不能直接作为各外设频率；三路CAN共享时钟来源也不要求三条总线采用相同位速率。
- **故障行为：**上电收发器默认态、DIR翻转到最后停止位、USB插拔、IMU中断/FIFO、Flash超时和错误恢复需要混合负载验证。

依据[H723数据手册](https://www.st.com/resource/en/datasheet/stm32h723vg.pdf)的DMA、USART、FDCAN和USB章节，以及现有[芯片分区与勘误复核](H723与H743数据手册复核及选型判断.md)。本轮没有声称完成上述性能测试。

## 6. VGT6是否还有余量，何时考虑ZGT6

CSV还给出以下**可选引脚层面共存**的资源，均未与上述基础接口重复：

| 可选功能 | 引脚 |
| --- | --- |
| 第5路通信串口 | UART8：PE1 TX、PE0 RX，AF8；若四路串口均给设备，上位机除USB外仍可另有串口 |
| I²C扩展 | I2C2：PB10/PB11，AF4 |
| SD卡四位模式 | SDMMC1：PC8～PC12、PD2，AF12；检测PE5用GPIO轮询，避免与IMU的EXTI5竞争 |
| IMU加热与NTC | PC6/TIM8_CH1 AF3、PC3_C/ADC3_INP1 |
| RGB与蜂鸣器 | PB7/TIM4_CH2 AF2、PC7/TIM3_CH2 AF2；与加热的TIM8分开 |
| 第二IMU片选 | PA15 GPIO，SYS只启用SWD，关闭完整JTAG |
| 安全握手 | PC13使能、PD10电源良好、PE3急停/EXTI3、PE6故障/EXTI6 |
| LSE预留 | PC14/PC15 |

安全禁止路径仍需由硬件及设备侧共同实现，不能仅依赖MCU中断。RGB和加热虽然在本候选中分开定时器，但DMA/波形及MOSFET时序未验证，旧H0-03不能据此宣称关闭。

**ZGT6的主要理由应是未来资源组合或制造供货，而不是本轮接口数量。**可考虑它的条件包括：

1. 需要FMC SDRAM、第二组外部存储接口，或更复杂的RAM/NOR同时访问架构。
2. 新增Ethernet RMII、USB HS外置ULPI、更多硬件流控/编码器/PWM等，导致100引脚方案频繁牺牲已有功能。
3. 希望保留更多调试/扩展和可选布线空间，且核心板能容纳20×20 mm封装本体及焊盘。
4. VGT6无法取得适合的交期，而ZGT6的实际供货与整板成本更合适。

这些是重新评估144引脚的触发条件，不是“144引脚一定能容纳所有功能”的承诺。当前PA1、PA7、PC4/PC5、PB12/PB13等与RMII有复用竞争；增加以太网时必须重新排表。ZGT6片内RAM/Flash并不比VGT6更多。[H723表1、表7/8](https://www.st.com/resource/en/datasheet/stm32h723vg.pdf)

| 非备份片内RAM | 560 KiB | 560 KiB | 1056 KiB；仍分多个域 |
| DTCM | 128 KiB | 128 KiB | 128 KiB |

| 当前硬要求 | 引脚级可行 | 数量满足；无需仅为本组接口升级 | 原生CAN数量不符合 |

内存/封装依据[H743 DS12110 Rev 11，表2及§3.3/§3.39](https://www.st.com/resource/en/datasheet/stm32h743vi.pdf)与[H723 DS13313](https://www.st.com/resource/en/datasheet/stm32h723vg.pdf)。商城价格是[当日快照](主控采购价格与封装取舍.md)，不能把无现货报价当成交期承诺，也不能直接当作与用户H743报价同一采购条件。

### 情形A：三路独立原生CAN继续为硬要求

H743无法替换。即使给它三颗收发器，也只能接两套控制器；同一路分支或增加接插件不产生第三条独立原生CAN。更多RAM、更低价格和更小封装不能补足这一硬件外设缺口。

在H743约¥50与VGT6页面¥50.80的条件假设下，芯片本身名义差额仅¥0.80；两者供货口径尚不同，更没有充分理由为这一差额引入额外CAN控制器和另一套驱动。此时优先推进VGT6的时钟/DMA与原理图候选；尺寸允许且供货合适时再用ZGT6。

### 情形B：允许两路CAN，或第三路改为外部控制器

若只需两路原生CAN，H743的约1 MiB级片内RAM、2 MiB双Bank Flash和8×8 mm本体都有实际价值，USB、SPI IMU、四路UART、QSPI NOR可按原方案作为迁移起点重新核验。它不会因480 MHz低于550 MHz就自然不适合下位机；应以同负载最坏耗时和内存峰值判断。

若需要第三条独立总线，但允许其控制器外置，可研究H743＋SPI CAN控制器。这会得到三条总线，但只有两路是MCU原生，必须明确改变需求。总成本增加外部控制器、时钟/供电等外围、SPI/片选/中断布线及驱动测试；第三路的SPI搬运、FIFO与服务延迟需按实际负载验证。外置SPI并非天然无法满足实时需求，但本项目尚无适用性证据，不能作为无代价替换。

### 整板成本与开发成本

- **BGA面积与装配：**H743VIH6本体更小；焊盘扇出、检测和返修与LQFP不同。应由实际工厂报价比较PCB/装配/良率，不预设必须增加板层，也不凭封装单独断言总价一定更高。
- **存储：**更大片内RAM可减少扩容压力，但当前H723基础版同样不要求外部RAM，因此不能预先把一颗“本来就没有的RAM”算成H743的节省。W25Q128是否能删应看升级/持久化分区，不由RAM容量决定。
- **软件：**两者同为M7，但存储域、Cache、RCC、USB实例、QSPI/OCTOSPI、ADC等仍需分别配置，不是二进制或焊盘直接兼容替换。
- **现有投入：**仓库尚无本板正式EDA/固件，不存在已完成PCB或固件必须保住的沉没成本。旧H743表能提供设计输入，但其RGB/加热共用TIM8、USB接入检测等问题仍需关闭。
- **硅版本：**若按H743 480 MHz设计，需确认实际硅修订满足条件；订货名中的V不是硅修订V。既有双CAN勘误也应按实际芯片修订检查，见[docs/12](H723与H743数据手册复核及选型判断.md)。

本轮建议：保持三路原生CAN时，优先H723VGT6候选；只有用户明确愿意改变CAN约束，才重新将H743列为可选基线。ZGT6作为资源扩展或供货备选，不能用更大封装代替需求和负载预算。
