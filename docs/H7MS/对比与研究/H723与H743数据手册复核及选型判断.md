复核日期：2026-10-11。适用项目：H7MS-Core-A1通用机器人实时控制平台。比较对象为达妙DM-MC02使用的STM32H723VGT6、用户参考板使用的STM32H723VGH6，以及当前规划STM32H743VIH6。本文记录芯片比较；用户随后确定三路原生CAN为硬要求，最新方向见[外部RAM方案](三路原生CAN与H723外部RAM方案.md)。精确替代型号未定，旧Pin Plan/Stack Interface v0.7仅作迁移输入。

## 1. 判断与适用边界

**达妙采用H723有充分的资源匹配理由：三条原生FDCAN、更大的缓存，以及CORDIC/FMAC适合部分实时运算。H743的主要优势是更大的片内存储、双Bank Flash及部分外设能力。二者不是简单的高低档关系。**

对H7MS，用户已确定三条独立原生CAN必须具备，H743不再符合需求。后续明确上下位机分工后，当前先比较G474/H723的片内RAM方案，外部RAM按实际缺口选配，见[docs/14](../共性研究/上下位机职责与IMU处理边界.md)；用户提出的N657列为[扩展研究候选](STM32N657L0H3Q候选评估.md)。H743的480 MHz硅版本V条件保留为技术对照。不能只为550 MHz换芯片，也不能只因H743总RAM较多就排除H723。

达妙没有在已归档资料中公开内部选型决策、采购价格或资源实测。本文能解释其设计为何合理，不能证明其真实商业动机，也不能断言它的固件用不完H723内存。参考板事实见[达妙独立评估](<../../达妙 DM-MC02/总结分析报告.md>)；四板历史比较保留原记录。

## 3. 精确资源比较

表中KiB按1024字节、MiB按1024 KiB计算，便于核算；缓存、FDCAN专用RAM不计入通用工作RAM。外设数量不保证所有信号能在100引脚上同时引出。

| 项目 | STM32H723VG | STM32H743VI | 对通用板的意义 |
| --- | --- | --- | --- |
| 内核/FPU | Cortex-M7，单/双精度FPU、DSP | Cortex-M7，单/双精度FPU、DSP | 基本软件计算能力同类 |
| CPU最高频率 | 550 MHz，有Boost/ECC条件 | 480 MHz，有硅版本/温度条件 | 不能直接换算实际控制性能 |
| 指令/数据缓存 | 32/32 KiB | 16/16 KiB | H723缓存更大，但收益依赖代码与数据工作集 |
| 数学外设 | CORDIC、FMAC | 无对应专用模块 | H723可卸载特定三角函数、定点滤波 |
| 用户Flash | 1 MiB，单Bank | 2 MiB，双Bank | H743有更多固件/恢复布局空间 |
| RAM总和，含备份区 | 564 KiB | 1060 KiB，通常概述为约1 MB | 必须再拆到各区，不能整体当作堆 |
| DTCM | 128 KiB | 128 KiB | 最关键的低延迟数据区容量相同 |
| 原生FDCAN | 3 | 2 | H723可多分一条独立物理总线 |
| FDCAN报文RAM | 三路共享10 KiB | 两路共享10 KiB | 总线数增加没有同步增加该缓存总量 |
| USB控制器 | 1个HS/FS控制器，内置FS PHY | FS及HS/FS，共2个控制器 | HS的480 Mbit/s均需外部ULPI PHY；USB-C不代表高速 |
| ADC最高硬件分辨率 | ADC1/2：16位；ADC3：12位 | ADC1/2/3：16位 | 电源/温度采样迁移要重核标定和量程 |
| USART/UART/LPUART实例 | 5/5/1 | 4/4/1 | 仍需逐路AF、DMA及并发分配 |
| 32位通用定时器 | 4 | 2 | H723有更多长计数资源；可引出通道另算 |

资源依据S1表1、S2表2及功能章节；RAM与报文RAM的推导见下文。H723没有NPU，FMAC的16位数据通路不会自动加速现有FP32神经网络，软件必须主动适配并验证数值误差。CORDIC同样是定点接口，不能等同于额外浮点内核。

## 4. 主频、TCM ECC与最坏耗时

S1表12给出VOS0下520 MHz，开启CPU_FREQ_BOOST才到550 MHz；表13规定VOS0最大结温105°C。S5 p.20～21明确，H72x/73x超过520 MHz时需通过Boost选项关闭TCM RAM的ECC，涉及ITCM和DTCM。不同文档也使用CPUFREQ_BOOST拼写。本结论不延伸为“所有RAM或Flash都关闭ECC”。

因此，若H723方案要求保留TCM ECC，应按不超过520 MHz设计并确认选项字节。550相对480的频率优势约14.6%；520相对480约8.3%。这是频率比例，不能承诺相同比例的执行时间改善。缓存命中率、Flash等待、分支、DMA总线竞争和数据位置都会改变结果。

S2表2脚注限定H743的480 MHz适用于硅版本V，并要求结温在−40～105°C内。**STM32H743VIH6料号里的V表示100引脚，不能据此识别硅版本V。**要用芯片标识及DBGMCU_IDCODE.REV_ID确认。

本项目的判断：先用520 MHz且保留TCM ECC作为H723候选测试条件；确有截止时间收益时再单独评估550 MHz。两颗芯片都以混合负载下的最大耗时和抖动决定是否合适。数据手册不同运行条件的典型电流，不能直接证明哪一块控制板更省电；板级稳压器、收发器、IMU加热和温升必须另算。

## 5. RAM差别主要在哪里

| RAM区 | H723VG | H743VI | 使用约束 |
| --- | --- | --- | --- |
| ITCM | 固定64 KiB＋可分配部分，最大256 KiB | 64 KiB | 关键代码；CPU/MDMA可达 |
| DTCM | 128 KiB | 128 KiB | 关键数据、栈；DMA1/2不能直接访问 |
| AXI SRAM | 固定128 KiB＋可分配部分，最大320 KiB | 512 KiB | 大缓冲/数据/代码，注意Cache及跨域访问 |
| ITCM/AXI共享容量 | 192 KiB，按64 KiB分配 | 无 | 不能同时取ITCM与AXI的最大值 |
| D2 SRAM1/2/3合计 | 16＋16＝32 KiB | 128＋128＋32＝288 KiB | 通信与DMA缓冲的重要区域 |
| D3 SRAM4 | 16 KiB | 64 KiB | BDMA可用区之一；还需按实际主设备核对 |
| Backup SRAM | 4 KiB | 4 KiB | 备份用途，单独预算 |
| 不含Backup的总和 | 560 KiB | 1056 KiB | 分散在多个地址区 |

H723的ITCM/AXI四种配置为64/320、128/256、192/192、256/128 KiB，合计始终384 KiB；依据S3表8与S1 §3.3。以ITCM最小配置、且不把ITCM/Backup用于普通数据为假设，H723其余区域合计496 KiB，H743为992 KiB。这是区域容量加总，不是单块连续可分配空间，也不是已测可用堆。

**H743不是多出一倍DTCM，而是多出大量AXI与D2/D3 SRAM。**这对于多串口环形缓冲、网络数据、USB、TF日志、任务栈和可选算法同时运行更有价值。H723的D2只有32 KiB也不等于所有DMA缓冲只能用32 KiB：DMA1/2可经总线访问AXI SRAM；BDMA可达范围更窄，不能照搬DMA1/2布局。两者的Cacheable DMA缓冲均需明确MPU属性、缓存维护和所有权交接。[S5]

注意资料差异：S5是跨型号应用笔记，其表5列出的H72x/73x SRAM4容量不能直接套到H723VG；本文按S1表1及§3.3的16 KiB核算。S5关于ITCM增量的措辞也以S3表8四种配置交叉确认，避免重复计算共享RAM。

## 6. 三路CAN和Flash升级的实际价值

三条CAN适合把不同报文负载、波特率或故障域分开，例如两组执行器加一组外部设备。H723可直接提供第三个控制器，仍需第三套收发器、保护与终端方案。H743若要第三条独立CAN，需要外部控制器或系统架构调整；SPI扩展会增加驱动、IRQ和共享总线调度工作。

S1 §3.42明确三路共享10 KiB报文RAM；S4 §56.4.2给出H743的2560个32位字及分区要求。滤波器、接收FIFO、发送缓冲和发送事件FIFO都要在总空间内安排，各控制器区域不得重叠。专用报文RAM与上一节工作SRAM是两类预算；RAM大不能替代FIFO深度和及时搬运，控制器多也不能替代带宽核算。

H743两块1 MiB Flash可支持跨Bank读与擦写，有利于下载新固件时继续执行另一Bank中的代码。H723单Bank的擦写会影响同Bank取指/读取，要保持关键任务运行，需要把相关代码、向量、常量及调用链迁至适当RAM，或明确进入停止控制的升级模式。依据S1/S2存储章节与S5 §2.5.1。

双Bank仍不等于自动获得可靠A/B升级：镜像大小、Bootloader、校验、回滚、断电恢复、跨Bank依赖都要设计。外部NOR可用于升级暂存、日志与资源文件，不能直接当成片内RAM，也不会使H723内部Flash变成双Bank。

## 7. 对当前引脚方案的影响

核对输入为[现有Pin Plan v0.7](../../../archives/2026-10-11_before-docs-v0.8.0/README.md)，尚未完成替代型号的全量球位/AF审查。

| 当前资源 | H723迁移时已发现的影响 | 需要的动作 |
| --- | --- | --- |
| PD12＝QSPI_IO1，PD13＝QSPI_IO3 | H723这对引脚也是FDCAN3_RX/TX，AF5 | 若启用第三路CAN，重新安排外部存储或其他资源 |
| H723其他FDCAN3管脚PF6/7、PG9/10 | S1表7中100引脚封装无这些管脚 | 不能用144引脚型号的AF选项解决100引脚冲突 |
| QUADSPI外设 | H723使用OCTOSPI；100引脚型号资源表只列1路 | 重核存储引脚、命令、时钟、驱动与勘误，不能照搬寄存器配置 |
| PC2_C/PC3_C使用ADC3测5V和NTC | H723 ADC3最高12位，H743为16位 | 核对输入通道、分辨率设置、采样时间、分压和标定；ADC位数不等于系统精度 |
| PA11/12 USB设备 | H723对应其HS控制器的内部FS PHY路径 | 重配USB控制器、时钟与中断；这对线本身不会提供480 Mbit/s |
| RGB/加热共用TIM8 | 换芯片不能消除现有共用时间基问题 | 仍按H0-03解决 |

封装应单独决策。H723VGT6为LQFP100，H723VGH6与H743VIH6为TFBGA100；H743也有LQFP100候选。LQFP便于探测/返修，BGA有面积优势，这些工程利弊不等同于H723/H743内核优劣。相同引脚数或封装名称不能证明电源球位、模拟引脚和AF兼容。

S1表1、S2表2脚注均显示所比较的100引脚封装不提供SDRAM接口能力；不能直接提出“外挂SDRAM补足内存”而不改封装和资源分配。H723的Octo-SPI可带来其他外部存储方案，但仍需明确存储器型号、可达性、最坏访问延迟和引脚代价。两者均有以太网MAC，增加网口还需要PHY、时钟、引脚与板级电路，当前A1尚未完成该分配。

## 8. 勘误怎样影响选择

| 问题 | 适用范围/依据 | 本项目处理 |
| --- | --- | --- |
| H743两路FDCAN并发时CPU可能读错报文RAM | S7 §2.24.2、表3：Y/W受影响且无规避方案；X/V列为不受影响 | 不能据此否定修订V的H743；采购与启动诊断记录REV_ID |
| FDCAN边沿过滤、特定Tx FIFO/专用缓冲优先级、DAR模式问题 | S6 §2.22；S7 §2.24.3～5 | 两者都需按启用模式落实规避措施，加入总线压力与仲裁测试 |
| EOT后过早关闭SPI可能截断输出 | S6 §2.21.5；S7 §2.22.6 | IMU驱动按相应勘误检查结束时序，用波形验证 |
| USB Host经Hub连接低速设备可能挂起 | S6 §2.23.1；S7 §2.25.3 | 与当前USB Device模式区分；未来新增Host时重新审查 |
| 以太网DMA/时间戳等限制 | S6 §2.24及S7对应ETH章节 | 采用网口/PTP时按具体配置补充审查，当前不宣称已解决 |

S7列出Y/W、X、V对应REV_ID为0x1003、0x2001、0x2003；S6列出A、Z为0x1000、0x1001。版本号必须结合器件型号解释。勘误页数多少不是可靠性排名，升级HAL也不能视为自动覆盖所有硬件限制。

## 9. 对H7MS的选择规则与下一步

| 明确需求 | 建议 |
| --- | --- |
| 两路CAN足够的其他项目（不适用于当前H7MS） | 可评估H743，480 MHz以修订V及电气条件为前提 |
| 三路独立原生CAN为硬性要求（当前已确定） | 优先评估H723＋外部RAM；关闭引脚冲突并重做RAM/Flash预算 |
| 现有任务算不完，但内存有余量 | 先比较Cache、数据位置、算法及加速器；用同负载实测520/550与480 MHz |
| 原型调试/制造不适合BGA | 独立评估LQFP方案，不把更换封装自动等同于更换芯片系列 |
| 同时要求三路CAN、大RAM和大量并行接口 | 扩大候选范围与封装评估；不强行在这两个100引脚型号中二选一 |

按以下证据完成H0选型关闭，当前均没有本板实测结果：

1. 落实三路CAN同时运行，列出每路节点、帧长、频率、突发量和故障处理时限。
2. 对两个候选分别生成精确料号的AF/时钟/DMA资源矩阵与链接布局，记录每块RAM的剩余字节、堆栈峰值、报文RAM分区及Flash升级布局。
3. 用相同混合负载测平均、P99、最大周期和丢包/溢出，不用单独CoreMark或主频比替代控制验收；覆盖Cache冷/热状态和TF写入突发。
4. H723记录TCM/AXI分配及Boost/ECC选项；H743记录硅版本。共同记录VOS、总线/外设时钟、编译器、优化、内存放置与温度。
5. 完成总线仲裁/恢复、DMA与Cache一致性、SPI末位波形，以及升级断电/回滚验证；在同等负载和供电条件下比较功耗。

这些结果形成后再更换基线。当前没有证据表明H743算力不足，也没有证据证明H723 RAM已经足够或不足。芯片数据手册可以确定能力和限制，最终选择还取决于本平台明确的接口组合与负载。
