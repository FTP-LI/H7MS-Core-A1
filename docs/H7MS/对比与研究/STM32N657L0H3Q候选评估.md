# STM32N657L0H3Q候选评估

> 历史选型研究，保留推导及来源。2026-10-11 已选定 STM32H735VGH6 + Direct SMPS；当前权威入口为[总结分析报告](../总结分析报告.md)及[引脚规划](../引脚规划.md)。本文旧候选建议不覆盖当前方案。

日期：2026-10-11；Docs v0.7.8。对象是用户提出的精确料号STM32N657L0H3Q，项目仍要求单主控至少三路独立原生CAN，上位机为树莓派类算力平台。

**结论：N657同时具备三路原生FDCAN和较大片内SRAM，值得作为高资源方案研究；它不是H723的直接替换件。A1基础负载尚未证明需要迁移，G474/H723比较继续，N657列为扩展候选，不冻结选型。**

## 1. 核验到的关键能力

| 项目 | STM32N657L0H3Q | 对A1的意义 |
| --- | --- | --- |
| CPU | Cortex-M55，最高800 MHz；表5注明800 MHz需overdrive模式，普通上限600 MHz | 增加计算余量，不能按主频比例直接推断最坏延迟 |
| SRAM | 手册标称4.2 Mbytes连续系统SRAM；另列TCM和备份等区域 | 比H723的系统RAM大，但应用可用量仍需扣除代码、系统和启用的算法/外设工作区 |
| TCM | 默认配置下128 KiB DTCM、64 KiB ITCM，可配置细节待参考手册复核 | 总RAM增大不意味着DTCM按同样比例增加；不要重复叠加可配置区域 |
| CAN | 三路原生FDCAN，共用10 KiB报文RAM；FDCAN1支持TTCAN | 满足控制器数量硬要求，但报文RAM没有因系统RAM变大而超过H723的10 KiB |
| 用户程序Flash | 无片内用户Flash | 正常独立启动须设计外部程序存储及启动链；Boot ROM/OTP不能当作用户Flash |
| NPU | Neural-ART，标称最高600 GOPS，NPU时钟最高1 GHz | 专用神经网络加速能力，不是CPU通用浮点算力 |
| 精确封装 | VFBGA223，10×10 mm，0.5 mm球距 | 需要重新评估扇出、板层、装配、检查和返修；不能照搬旧100引脚板 |

CPU、内存、CAN来自[DS14791 Rev 11，2026-09，表5、§3.1/3.2/3.50](https://www.st.com/resource/en/datasheet/stm32n657x0.pdf)。精确L0料号的封装、三路CAN和产品状态也由[ST L0产品页](https://www.st.com/en/microcontrollers-microprocessors/stm32n657l0.html)交叉核对。所有实例数都还需要精确封装AF矩阵证明能与存储、上位链路、IMU及串口同时引出。

本次未完成RAM地址/可达性、TCM重分配及全部引脚组合的详细设计，不把4.2 MB直接写成可分配堆容量。H723对照以[既有手册复核](H723与H743数据手册复核及选型判断.md)为准。

## 2. 与刚讨论的W25Q128有什么关系

两种架构下外部NOR的角色不同：

```text
H723xG
  片内Flash：可以保存并启动主程序
  片内RAM：运行工作区
  外部NOR：按需求保存升级镜像、配置和资源

N657
  Boot ROM：芯片内固化的启动代码
       ↓ 从外部程序存储读取FSBL到片内RAM
  FSBL：初始化系统并启动应用
       ├─ Load and Run：复制应用到RAM运行
       └─ XIP：配置外部Flash后从其映射地址执行应用
```

N6没有嵌入式用户Flash，ST的[架构说明](https://wiki.st.com/stm32mcu/wiki/Security%3ASecurity_features_on_STM32N6_MCUs)明确区分ROM、OTP和外部程序存储。[UM3234 Rev 5](https://www.st.com/resource/en/user_manual/um3234-how-to-proceed-with-boot-rom-on-stm32n6-mcus-stmicroelectronics.pdf)规定启动介质、引脚和镜像格式；还支持串口/USB下载启动，因此“外部存储”不是实验室每次运行代码的唯一方法，但本项目正常独立上电应有可靠的本地启动介质。

W25Q128这一类串行NOR可以作为研究方向，但尚未证明W25Q128JVPIQ与本设计的N6启动接线完全兼容。要核对Boot ROM读取命令、固定启动引脚、I/O电压域、上电默认模式及外部下载器；不能把3.3 V器件接到任意N6存储引脚，也不能把H723的初始化代码直接复用。

外部RAM依然不是必配项。若选择Load and Run，应用代码会占片内RAM，余量必须重新计算；若选择XIP，则需评估外部Flash等待、Cache未命中，以及擦写时代码读取冲突。ST提供两种模板，见[AN6197的Template_FSBL_LRUN/XIP](https://www.st.com/resource/en/application_note/an6197-stm32cube-mcu-package-examples-for-stm32n6-mcus-stmicroelectronics.pdf)。

## 3. 大内存与NPU的实际价值

不使用NPU也可以使用N657的大SRAM和M55；若下位机确实需要复杂本地估计、较大的有界工作区或更多并发接口，它可能有价值，不能仅因其AI定位就排除。

若希望下位机承接神经网络策略或局部视觉，需要先导出真实模型并检查量化、算子、内存及总线开销。600 GOPS不等于PID、AHRS或任意C代码都获得相同比例加速。ST工具对不能映射到硬件的算子可能生成M55回退代码，见[Neural-ART算子与限制](https://stm32ai-cs.st.com/assets/embedded-docs/stneuralart_operator_support.html)；部署成功后仍需做数值和并发截止时间验证。

目前上位机已承担视觉、整机融合和复杂控制，A1基础版只需通信、采集、目标调度、故障处理及可选轻量AHRS。这个分工下，N657的高资源能力还没有对应到必须实现的负载。它仍是MCU，不因带NPU而具备树莓派类通用Linux算力平台的全部能力。

## 4. 迁移代价与需要实测的部分

- **电路重做**：精确封装、SMPS及不同电源/I/O域、时序、去耦和启动存储都需要新设计；依据[AN5967硬件开发指南](https://www.st.com/resource/en/application_note/an5967-getting-started-with-hardware-development-for-stm32n6-mcus-stmicroelectronics.pdf)，不直接沿用旧H743/H723电源方案。板层数量与成本由实际扇出和厂家能力决定，不在此预设。
- **启动与升级重做**：建立外部Flash下载器、FSBL、应用布局、冷启动、损坏镜像恢复和断电升级验证；开发调试成功不等于独立上电成功。
- **软件与隔离配置重审**：CPU、工具链、DMA/Cache、TrustZone/资源访问控制与中断优先级均需重新适配。CAN、IMU、上位链路的语义和上层设备接口可以保留。
- **确定性验证**：重点比较CAN/采集与CPU/NPU/外存并发时的数据年龄、最坏延迟和内存峰值。较高算力不自动消除共享总线争用。
- **成本和供货**：本次官网标为Active，但页面未给出可用采购报价和库存数字；不据此承诺现货、功耗或成本高低。需要比较整板BOM、工艺及研发投入。

## 5. 勘误初筛

本次检查[ES0620 Rev 5，2026-08](https://www.st.com/resource/en/errata_sheet/es0620-stm32n6xxxx-device-errata-stmicroelectronics.pdf)的适用范围及FDCAN章节，未宣称完整电路已经满足全部勘误。

与三路总线调度直接相关的条目包括：§2.14.1特定边沿过滤条件下接收失步、§2.14.2专用Tx Buffer与Tx FIFO混用且优先级满足特定条件时发送次序反转、§2.14.3禁止自动重传模式下特定仲裁丢失导致发送失败。可按官方方法禁用相关过滤、选择发送队列策略及处理失败重发；最终方案需结合确切硅修订验证，不能因系列较新就假定没有外设限制。

## 6. 当前建议与下一步

| 需求方向 | 当前评估路线 |
| --- | --- |
| 基础通信、采集和故障处理，资源预算较紧凑 | 继续验证G474xE是否满足全部并发要求 |
| 保持当前上下位机分工，希望有较多片内余量 | 优先验证H723xG＋串行NOR、无外部RAM的方案 |
| 确需数MiB片内工作区、复杂本地算法或神经网络加速 | 将N657与H723方案做同负载对比，接受新的启动与板级设计工作 |

N657并未被否决，也没有取代当前基础版候选。决定前先在可获得的官方/成熟开发板上验证实际算法和通信，确认冷启动、片内RAM占用和端到端时序；随后才为L0H3Q精确封装建立资源矩阵和BOM。开发板可能采用其他封装，运行验证与L0引脚证明应分别记录。
