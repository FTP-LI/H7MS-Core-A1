# OTA 分区与实施验证计划

2026-10-12 · 容量预留及实施门槛，不是已冻结的链接脚本、Flash map 或已通过的测试。

## 内部 Flash 初步预算

H735VGH6 用户 Flash 为 1 MiB、8 × 128 KiB。**System Memory 中的 ROM Bootloader 不属于这 1 MiB 应用分区，也不能拿来存放自定义 Bootloader。**器件依据见 [DS13312 §3.3.1](https://www.st.com/resource/en/datasheet/stm32h735ig.pdf)。

以下地址区间采用 **左闭右开**，结束地址不属于该区域。

| 区域 | 起始地址 | 结束地址（不含） | 容量 | 用途 |
| --- | --- | --- | --- | --- |
| 自定义 Bootloader | `0x08000000` | `0x08020000` | 128 KiB / sector 0 | 启动供电、验签、安装/恢复、最低维护通道 |
| 主应用槽 | `0x08020000` | `0x08100000` | 896 KiB / sector 1–7 | 镜像头 + 应用 + 校验/签名/状态等算法开销 |

128 KiB 是 Bootloader 的初始预算，是否放得下加密库、USB/UART、NOR 驱动及恢复逻辑，必须以真实构建 map 为准。若需要 256 KiB Bootloader，主应用槽将缩至 768 KiB；此时链接地址、签名参数和所有分区必须一起调整。

**896 KiB 不是净应用容量。**例如采用需要按内部扇区预留 trailer 的交换算法时，若 trailer 占一个 128 KiB 扇区，剩余只有 768 KiB，再扣镜像头、TLV、签名等。不能先把应用编满 896 KiB 再补 OTA。

内部 A/B 备选可预算为 Boot 128 KiB + A 384 KiB + B 384 KiB + scratch/元数据 128 KiB，各槽有效载荷还需扣除开销。由于 128 KiB 擦除边界，不能将剩余 896 KiB 简单平分成两个 448 KiB 可独立擦写槽。这一备选只用于容量比较，未选定具体算法。

## W25Q128 的外部容量预留

W25Q128JV 为 16 MiB。下表是项目的**功能容量预算**，不是可直接导入 MCUboot 的分区文件；偏移以 NOR 芯片起点为零，不能当成 MCU CPU 地址。

| 区域 | 起始偏移 | 结束偏移（不含） | 容量 | 目的 |
| --- | --- | --- | --- | --- |
| 状态 A | `0x000000` | `0x010000` | 64 KiB | 更新事务日志/冗余状态预留 |
| 状态 B | `0x010000` | `0x020000` | 64 KiB | 另一擦除区域的有效状态副本 |
| 候选/交换槽 | `0x020000` | `0x120000` | 1 MiB | 接收新固件；交换算法下也可能变成旧镜像槽 |
| 已知可用镜像预留 | `0x120000` | `0x220000` | 1 MiB | 独立恢复副本的容量；是否采用取决于最终算法 |
| 工作区预留 | `0x220000` | `0x240000` | 128 KiB | 大扇区搬运/scratch 候选；算法不用时可保留 |
| 参数区 | `0x240000` | `0x280000` | 256 KiB | 含版本的配置及迁移副本 |
| 日志/资源余量 | `0x280000` | `0x1000000` | 13.5 MiB | 日志、资源和后续扩展 |

合计 16 MiB，无重叠。前 2.5 MiB 包含 OTA 及参数预留，**并非 OTA 框架必须占用 2.5 MiB**。两份 64 KiB 状态区为预留上限，不要求每次升级擦写完整 64 KiB。

若采用 MCUboot 交换，旧镜像通常由其 secondary slot 保存；不要再写一套旁路状态机去擅自覆盖这个区域。独立恢复槽可以暂不启用，或者在另行验证的工厂恢复方案中使用。若改用“候选 + 已知可用副本 + 可恢复复制”，它是另一种安装设计，需要完整论证备份完成、擦写进度、状态提交和回退，不是 MCUboot 配置项的简单别名。

最小规则：可用旧镜像的备份/恢复关系必须在擦除内部应用前建立并校验；新镜像未确认前，不准回收最后一个有效旧镜像及它所需的参数。复制恢复镜像本身也可能掉电，必须有明确可重复执行的阶段。外部 NOR 的 256 B 页编程和 4/32/64 KiB 擦除规则见[原厂手册](../H7MS/技术依据/外围器件/W25Q128JV_RevF.pdf)。

## MCUboot 移植优先验证项

目前只将 MCUboot 列为优先验证对象，尚未选版本或安装算法。

| 检查点 | H7MS 的具体问题 | 通过条件 |
| --- | --- | --- |
| 异构擦除大小 | 内部 128 KiB，外部 4/32/64 KiB | 明确驱动暴露的 sector geometry，验证边界、擦写与重启恢复 |
| swap-using-offset | 官方要求槽位扇区布局/大小一致；secondary 多一个扇区较省空间 | 若将外部空间逻辑聚合为 128 KiB 单位，须证明所选驱动/算法确实支持并通过掉电测试；不能仅修改常量 |
| swap-using-scratch | scratch 至少容纳最大被交换扇区 | 128 KiB 只是容量下限；官方提示未来可能移除此算法，采用须固定版本并记录维护计划 |
| overwrite-only | 可覆盖主槽，但不能据此宣称具备旧版自动回退 | 首版恢复目标不满足时不选；增加恢复机制必须重新审查 |
| 写入对齐与状态 | 内部 Flash 32 B word + ECC，NOR 页边界不同 | 核查所选版本的写对齐、trailer/status 编码、擦除值及不可重复编程规则 |
| 外部驱动 | 当前只有引脚规划，没有 Boot 级 OCTOSPI 驱动 | Boot 独立冷启动可读/写/擦 NOR，处理忙、保护与失败，无应用依赖 |
| 启动体积 | 供电初始化、验签、NOR、维护通信共同占空间 | 保存链接 map、RAM 峰值和栈余量；超过预算先调整分区 |

算法条件及维护提示来自 [MCUboot Design](https://docs.mcuboot.com/design.html)，移植边界见 [Porting how-to](https://docs.mcuboot.com/PORTING.html)。上述 1 MiB 外部候选预算可容纳 896 KiB 主槽加一个 128 KiB 单位，但这只证明空间足够，不证明 Flash map、最大净镜像或掉电行为已正确。

## 包格式与传输预算

升级包至少包含：产品/板型 ID、硬件版本范围、固件版本、安全版本、最低 Bootloader 版本、上位机协议兼容范围、镜像长度、镜像哈希、签名算法/密钥 ID、签名。若使用 MCUboot，应扩展/使用其签名覆盖的镜像元数据，避免维护一份未签名且可改变安装目标的外部清单。安装地址由板端可信布局约束，不接受上位机任意指定写 Flash 地址。

传输帧包含会话标识、目标镜像、偏移、长度、序号和校验，支持幂等重试、状态查询和终止。持久进度的有效性以板端读回/校验为准。断电后对未提交扇区重新擦写或按框架恢复，不能从一个未经确认的字节偏移直接追加。

以 1 MiB **传输文件**计算 UART 8N1 的理想最低时间：`字节数 × 10 / 波特率`。115200 baud 约 91 s；1 Mbaud 约 10.5 s。这里的 1 MiB 是算例，不代表主应用净容量；实际还需加帧、重试、擦写、验签与启动时间。USB FS 的 12 Mbit/s 是线路速率，不承诺固定下载秒数。

首版可从 1–4 KiB 接收块、双缓冲开始测量；这只是试验起点，加密库、通信栈、栈空间及 Flash 驱动 RAM 另计。内部 128 KiB 擦除扇区不意味着必须分配 128 KiB RAM：读取/写入可以分块，恢复算法所需 scratch 则按存储介质预算。

## 分阶段落实

| 阶段 | 工作 | 可审查的完成证据 |
| --- | --- | --- |
| O0：固定基础 | 固定工具链、Cube/HAL/Boot 框架版本；Direct SMPS 启动；内部 Flash/NOR 基础驱动 | 版本清单、map、最小读写与冷启动日志 |
| O1：本地可靠更新 | UART8 完整包、验签、Boot 恢复通道，正常更新/回退 | SWD 可救援的样机演示、错误包拒绝记录 |
| O2：断电与坏固件 | 覆盖下载/安装/回退/确认各阶段故障注入 | 可重复的断电脚本/夹具、故障矩阵、镜像及状态哈希 |
| O3：上位机代理 | Linux 下载和 USB/UART 下发、断线重连、版本协商 | 端到端日志，应用失效时仍能经 Boot 维护恢复 |
| O4：发布管理 | 签名密钥流程、灰度、撤回、设备版本盘点、主从兼容策略 | 发布记录、失败设备清单、升级/回退操作说明 |

先完成 O1/O2，再声称支持可靠 OTA。OTA 包签名、Bootloader 自检和链路调度应在本地就能验证，不需要先搭建设备云。

## 必须覆盖的故障测试

| 注入点/故障 | 期望结果 |
| --- | --- |
| 下载时断网、拔 USB、上位机重启 | 旧应用仍可启动；重连按持久有效进度续传或重发 |
| 候选 NOR 页编程/扇区擦除时掉电 | 部分候选不被当作完整镜像；旧镜像不受影响 |
| 旧版备份过程中掉电 | 不提前擦除唯一内部有效应用；重启后能重做备份 |
| 内部每个扇区擦除/写入时掉电 | Boot 可续做或回退，不执行半写应用 |
| 状态日志提交、擦除旧状态时掉电 | 至少有一份有效状态；不依赖半写标志位 |
| 镜像缺尾、错误签名/板型、长度溢出、重复/乱序包 | 拒绝安装，不越界破坏 Boot、参数或已知可用镜像 |
| 新应用 HardFault、死循环、供电模板错误、通信初始化失败 | 看门狗/未确认复位触发回退；供电死锁还需验证冷重启恢复路径 |
| 回退安装过程中再次掉电 | 重启后仍能完成恢复，不能把回退当作天然原子动作 |
| 参数迁移后新版失败 | 旧应用能读取恢复参数；标定/身份信息不丢失 |
| NOR 读失败、无有效应用、日志区写满 | 输出禁止，停留维护并报告故障；不可误判为升级成功 |
| 后台下载叠加三 CAN、四 UART、IMU、USB | 测量最坏延迟/丢包；超预算可暂停下载，安装仍停机 |
| 健康确认与安全版本提交边界掉电 | 不提前拒绝仍需用于恢复的旧版本，不出现永久重启循环 |

每个擦写/状态边界应覆盖确定性断电点，并补充随机时刻中断及连续更新/回退循环。测试数量、看门狗期限、维护超时和性能阈值在样机阶段冻结；本次没有硬件，不能给出“已通过次数”或可靠性百分比。

首版验收应分别给出：下载结果、安装结果、试运行结果、确认版本、回退原因。Bootloader 自更新、分区表更新、Option Bytes 修改及远程修改供电配置不纳入首版验收。
